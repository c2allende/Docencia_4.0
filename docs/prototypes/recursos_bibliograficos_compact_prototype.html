Comparación UX/UI: M3 actual vs. Propuesta

  • Altura estado cerrado (propuesta): ~72px (solo barra colapsable). Sin impacto visual en la página: 0% de scroll al entrar.
  • Altura estado abierto (propuesta): ~720px para 4 recursos (~180px c/u). Cada tarjeta compacta reemplaza ~550px de la versión actual.
  • Ahorro de espacio vertical: ~70% en estado abierto, ~97% en estado cerrado vs. M3 actual (~2400px → ~72px cerrado).
  • Divulgación progresiva doble: Panel exterior (ver/ocultar lista) + details interno (ver/ocultar resumen). El usuario controla qué ve y cuándo.
  • Botón siempre visible: .btn .btn-primary oficial en .bibliographic-resource__actions, fuera del <details> interno. Sin dependencia de JavaScript ni stopPropagation.
  • Cita visible por defecto: Lo que el usuario necesita escanear para decidir si el recurso es relevante. Resumen bajo demanda.
  • Sin JavaScript: 100% HTML nativo con <details>/<summary>.
  • Consistencia entre módulos: Mismo patrón para M1, M2, M3. Actualmente hay 3 implementaciones visuales distintas que confunden al usuario.
  • Mobile: Recursos apilados verticalmente, botones a ancho completo (área táctil cómoda), cita legible en font-size-xs.

Recomendación UX/UI

  • Unificar los 3 módulos (M1, M2, M3) bajo el mismo patrón .bibliographic-resources con panel exterior colapsable + tarjetas compactas.
  • Preservar contenido textual exacto de cada recurso. No resumir citas, no abreviar títulos, no modificar resúmenes. La comparación de esta entrega ya lo demuestra: todo el contenido es idéntico al original.
  • Usar .btn .btn-primary oficial para todos los botones de descarga. Ubicar el botón fuera del <details> interno para evitar problemas de stopPropagation.
  • Mantener cita visible en la tarjeta compacta (es lo que el usuario necesita escanear para decidir relevancia). Resumen oculto bajo <details> interno.
  • Eliminar progresivamente compact-biblio-* y biblio-item de M1/M2/M3 después de migrar. Los estilos actuales pueden coexistir durante la transición.
  • Mover CSS definitivo a main.css bajo /* Bibliographic Resources Compact — Recursos */, después de aprobar el prototipo.

Riesgos

  • Regresión visual en M1/M2: Tienen estilos compact-biblio-* en main.css y también en línea en cada HTML. Asegurar limpieza al migrar. Crear backups antes de producción.
  • Accesibilidad: Verificar que <details> anidados tengan contraste suficiente y foco visible. El prototipo incluye :focus-visible en el summary del panel.
  • Enlaces a PDFs con espacios y caracteres especiales: Los enlaces originales (especialmente en M1) contienen espacios, tildes y dobles extensiones .pdf.pdf. Verificar que el servidor los sirva correctamente.
  • Sin JavaScript: El patrón funciona 100% con HTML nativo. No introducir dependencia de JS.

CSS para main.css

Las clases .bibliographic-resources, .bibliographic-resources__panel, .bibliographic-resources__summary, .bibliographic-resources__summary-title, .bibliographic-resources__summary-count, .bibliographic-resources__summary-action, .bibliographic-resources__summary-arrow, .bibliographic-resources__list, .bibliographic-resource, .bibliographic-resource__main, .bibliographic-resource__tag, .bibliographic-resource__title, .bibliographic-resource__citation, .bibliographic-resource__details, y .bibliographic-resource__actions se agregarían a main.css bajo /* Bibliographic Resources Compact — Recursos */, después de los estilos compact-biblio-* existentes. Los estilos actuales pueden coexistir para migración progresiva.
